Services
- Services in Linux can help you to configure software to run in the background and makesure they run all the time automatically when server reboots
----------------

$: service httpd start 
       or
$: systemctl start httpd

Here, Systemctl is the command used to manage services on a system manage server.

$: systemctl stop httpd   --> to stop HTTPD service
$: systemctl status httpd --> to check HTTPD service
$: systemctl enable httpd --> to Configure HTTPD service to start at startup
$: systemctl disable httpd --> To Configure Httpd not to start at startup.

To Create a service:
$: cd /etc/system/system
$: vi my_app.service     --> my_app.service is a unit configuration file
[Unit]                     --> This is used to provide metadata of this application.
Description=My python web application  

[Service]
ExecStart=/usr/bin/python3 /opt/code/my_app.py    --> Exact command to run this application
ExecStartPre=/opt/code/configure_db.sh            --> used to configure service should run before app runs
ExecStartPost=/opt/code/email_status.sh           --> used to configure service should run after app runs
Restart=always                --> This is used to restart if application crashes

[Install]                    --> It is used to configure a service should be up, post that our service will start at boot up, in this case multi-user.target will be running at bootup, post that our service will run.
WantedBy=multi-user.target         
$: systemctl daemon-reload --> to let system know that a new service is configured.
$: systemctl start my_app.service 
$: systemctl enable my_app.service

DNS
-------------
DNS Server --> Update /etc/hosts file with all servers and their hostnames
Worker servers --> update /etc/resolv.conf with nameserver DNS_SERVER_IP --> so that worker servers communicate with each other using names instead of ip.

$: nslookup domain_name --> to see domain ip and details
$: dig domain_name --> works same as nslookup

A record maps domain name with ipv4 address
AAAA record maps domain name with ipv6 address
cNAME record maps domain name with name

Java
----
Install Java:
1. Visit the Java Development Kit Archive.
https://jdk.java.net/archive/
2. Use the curl command to download the JDK archive directly into /opt:
$: sudo curl https://download.java.net/java/GA/jdk20/bdc68b4b9cbc4ebcb30745c85038d91d/36/GPL/openjdk-20_linux-x64_bin.tar.gz \
--output /opt/openjdk-20_linux-x64_bin.tar.gz
3. Extract the JDK archive into /opt:
$: sudo tar -xf /opt/openjdk-20_linux-x64_bin.tar.gz -C /opt/
4. Verify the installation by checking the version:
$: /opt/jdk-20*/bin/java -version
5. Set path variable with the command export PATH=$PATH:/opt/jdk-20/bin

JDK(Java Development Kit)
It is a set of tools that will help you develop, build and run java applications on a system.

Develop:
jdb  -- java debugger tool
Javadoc -- java document tool to document the code

Build:
javac -- Once source code is developed to build and compile your application using the javac tool.
jar  -- JAR Tool helps archive the code and related libraries into a single jar file.

Run:
JRE (Java Runtime Environment) -- A JRE is needed to run a java application on any given system.
java  -- java command line utility or the loader that is used to run the application.

Java Build & Packaging:
-----------------------

1. Deploy Source code 

MyClass.java
public class MyClass {
 public static void main(String[] args) {
   System.out.println("Hello World");
}
}

2. Compile

javac MyClass.java

3. Run

java MyClass

Source Code ---Compiler--MyClass.class  --JVM--Machine code

Above process is for a single file, but in reality many files will be there so packaging comes in

Package:
--------
$: jar cf MyAPP.jar MyClass.class Service1.class Service2.class .....
MyApp.jar

Run
$: java -jar MyApp.jar

Document:
---------
$: Javadoc -d doc MyClass.java

Build Process:
-------------
1. Develop    ---- Source code
2. Compile    ---- javac MyClass.java
3. Package    ---- jar cf MyClass.jar
4. Run        ---- java -jar MyClass.jar
5. Document   ---- Javadoc -d doc MyClass.java

If it comes to large applications we can't proceed with this process, so we are depending on other build tools.

NodeJs:

Node.js took javascript out of the web browsers and onto the server side.

1. Run the following script to install the latest lts version of nodejs:

# Download and install nvm:
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.3/install.sh | bash

# in lieu of restarting the shell
\. "$HOME/.nvm/nvm.sh"

#Install node using nvm
nvm install --lts

2. Add node to system wide PATH using the command:

sudo install -m 755  $(which node) /usr/local/bin/

3. Verify installation using the command:
node -v
